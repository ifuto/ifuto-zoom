# ifuto-replay

Minecraft (Fabric / **1.21.11**) 用の **パケット保存式録画 Mod** です。

録画中は「サーバーとやりとりしたパケットをそのままファイルに書き出す」だけなので**超軽量**。
あとでそのパケットを再生しながら描画するので、**出力時に FPS・解像度・ビットレートを自由に選べます**。
**「よし、ここから録る」と思った時点から録り始められます**（途中から録った録画も、いまの世界の写しを
一緒に保存するので再生できます）。

<img src="src/main/resources/assets/ifuto-replay/icon.png" alt="Ifuto Replay" width="220">

> [!NOTE]
> この README は **録画コア（パケットの保存）・再生プレビュー・動画の書き出し** の説明です。
> 「途中から録り始めた」録画も、いまの世界の写しを一緒に保存するので再生できます。
> カーソルや **入力中の文字** など、サーバーへ届かない操作も記録しています。
> 音声（**Minecraft だけ** / **PC 全体** / VC の声だけ、から選べる）も一緒に録れます。

## しくみ（なぜ軽いのか）

普通の「画面録画」は 1920×1080 / 60fps で **毎秒 300MB 以上** の絵を処理します。
パケット保存式は、同じ時間に **数十KB〜数百KB** しか仕事がありません。
（音声を録るときも、エンコードは外の ffmpeg に任せるのでゲーム側の仕事は増えません）

| | 画面録画 | ifuto-replay（パケット保存） |
| --- | --- | --- |
| 録画中の仕事 | 毎フレーム画面を読んで圧縮 | 届いたパケットを直列化してキューに積むだけ |
| 60fps を維持できるか | 重い設定だと厳しい | 描画には一切触らないので影響ほぼゼロ |
| 出力時の自由度 | 録った時点で固定 | **あとから FPS / 解像度 / ビットレートを選べる** |
| 視点 | 録った視点のみ | パケット＝世界そのものなので、カメラを自由に動かせる |

録画中に実際にやっていること（軽量化の中身）:

1. **のぞく場所は1か所だけ**
   `ClientConnection#channelRead0`（受信）と `ClientConnection#send`（送信）に Mixin を1本ずつ。
   どちらもシングルプレイ・マルチプレイ両方で必ず通るので、ここだけで全部取れます。
   PLAY フェーズ（パケットリスナーが `ClientPlayNetworkHandler`）以外は無視します。
2. **録画していないときのコストは `null` チェック1回**
   キーバインドの処理も含め、ふだんは何もしません。
3. **直列化は受け取ったスレッドで即座に**
   パケットは「あとで中身が変わる」可能性があるので後回しにできません（ReplayMod も同じ方針）。
   対応表は自作せず、バニラの `PlayStateFactories` のコーデックを借ります。バージョンが上がっても追従できます。
4. **ファイルIOと圧縮は別スレッド**
   ゲーム側は `offer()` でキューに積むだけ。**満杯なら捨てます**（絶対にゲームを待たせない）。
   捨てた数は録画終了時のログとカウンタに出ます。
5. **コピーは最小限**
   パケットの中身は Netty の `ByteBuf` のまま書き込みスレッドへ渡し、書き終わった側で `release()`。
6. **同じ種類のパケットは2回目から番号だけ**
   識別名を毎回書かない（最初の1回だけ定義フレームを書く）。
7. **維持用パケットは除外できる**
   KeepAlive / Ping などは再生に影響しないので既定で捨てます。
8. **メモリに溜めない**
   書き込み待ちのデータは **定期的に（既定2秒ごと）ファイルへ移します**。
   メモリに持てる量は **環境（割り当てられたメモリの大きさ）から自動で決めます**（固定も可）。
9. **容量が尽きる前に止める**
   保存先の空きが設定値（既定 1 GB）を切ったら知らせ、
   **さらに少なくなったら（既定 256 MB）録画を保存して自動で止めます**。
10. **世界の写しの直列化は書き込みスレッドで**
    区間切替・保存のたびにチャンク169個ぶんを変換するとクライアント側が一瞬止まるので、
    種類の登録だけその場で済ませて本体は別スレッドに回します（順番はキューが守る）。
11. **圧縮の既定は「強」**
    「最強」は少し縮むかわりに倍近く重いので既定は「強」（容量差は1%未満）。
    もっと軽くしたいときは設定で「標準」以下にできます。

## つかいかた

**キーバインドはありません。操作はぜんぶボタンです。**

ポーズメニュー（**ESC**）の**左上**に、Flashback と同じようにボタンが並びます。

| ボタン | 内容 |
| --- | --- |
| `● 録画開始` / `■ 停止 0:12` | 録画の開始と停止。録画中はボタンに経過時間が出ます |
| `⚑ しおり` | いまの時刻にしおりを付けます（録画中だけ押せます） |
| `≡ 録画一覧` | 保存した録画の一覧。日時・長さ・サイズ・接続先が見えて、削除もできます |
| `⚙ 設定` | 設定画面を開きます |

- 録画中は画面の隅にも `● 0:12  4.2 MB` のように出ます（位置・表示は設定で変更可）
- ファイルは **ゲームフォルダの `ifuto-replay/`** に `2026-09-13_01-23-45.ifreplay` という名前で保存されます
- サーバーから抜けたとき / ゲームを終了したときは、自動で保存して閉じます
- 録画一覧は**ヘッダとファイル末尾の12バイトだけ**を読むので、本体が何GBあっても一瞬で出ます

ファイル形式の詳細は [`docs/replay-file-format.md`](../docs/replay-file-format.md) を参照。

## 再生（プレビュー）

録画一覧の **「再生」** ボタンから、保存したパケットをそのまま世界として再生できます。

- 再生すると **いまのワールド/サーバーから切断されます**（確認画面が出ます）
- 画面の下に操作バーが出ます。**背景を暗くしないので、うしろで世界がそのまま動いています**

| ボタン | 内容 |
| --- | --- |
| `⏮` | 最初からやり直す |
| `❚❚` / `▶` | 一時停止 / 再生 |
| `1×` | 倍速（0.25× → 8× を順に切り替え） |
| `⚑ ◀` / `⚑ ▶` | 前 / 次のしおりへ移動 |
| バー | ドラッグで好きな時刻へ（しおりは黄色い印） |
| `リソースパック` | バニラのリソースパック画面を開く。**再生中に切り替えてすぐ反映されます** |
| `シェーダー` | **Iris のシェーダー選択画面**を開く（Iris が入っていないときは押せません） |
| `視点` | 一人称 / 三人称 / 三人称(前) |
| `住所` | サーバー住所の表示・非表示（`********`） |
| `✕` | 再生をやめて録画一覧へ戻る |

しくみ:

- **世界はぜんぶバニラが作ります。** 録っておいた S2C パケットを `ClientPlayNetworkHandler` に
  `packet.apply()` するだけなので、対応表を自前で持たずに済みます
- **送信はゼロ。** 何も送らない接続（`send` を潰した物）を渡しているので、
  サーバーがいないのにバニラが世界を組み立ててくれます
- **カメラは録っておいた自分の移動パケット（C2S）から復元** し、間を補間します
  （1フレームごとに位置を更新するので 60fps でも滑らか）
- **レジストリ（バイオーム・次元など）の写し** をファイルの先頭に残しているので
  （設定 `レジストリを保存`）、**録画ファイル単体で**再生できます
- **途中から録り始めた録画も再生できます。** 録り始めの世界を「サーバーが送ってきたのと同じパケット」
  として組み立てて先頭に置いているからです（次の章を参照）
- パケットは前向きにしか流せないので、**前に戻るときは最初から作り直して早送り**します
  （大きな録画でも固まらないよう、早送りは1フレーム数ミリ秒ずつに分けています）

### シェーダーとリソースパックをあとから変えられる

再生は「普通の世界を普通に描いている」だけなので、**Iris のシェーダーもリソースパックもそのまま効きます**。
操作バーからそれぞれの画面を開いて変えれば、再生中の見た目にすぐ反映されます
（例: 録ったときは軽い設定で、書き出し前にシェーダーを盛る、といった使い方ができます）。

Iris との連携は **Iris の API（`IrisApi.openMainIrisScreenObj`）を反映で呼ぶだけ** なので、
Iris が入っていなくてもこの Mod は動きます（その場合はボタンが押せなくなります）。

### サーバー住所を隠す

操作バーの **「住所」** ボタン、または設定の **「サーバー住所を隠す」** を ON にすると、
プレビューと書き出しで接続先を `********` と表示します（長さも中身もわかりません）。

- 既定は **OFF**。一度 ON にすると **次回以降も引き継がれます**（もちろん OFF に戻せます）
- 隠すのは**画面に出す文字だけ**。録画ファイル本体には残るので、後から元に戻せます
- 録画一覧の表示は隠しません（どのサーバーの録画か探すため）

## 途中から録り始めた録画（世界の写し）

**「よし、ここから録るぞ」と思った時点から録り始められます。**
パケット録画は「世界を作る最初のパケット」が無いと再生できないのですが、
サーバーに取り直しを頼むことは（通信を一切増やさないため）しません。代わりに
**すでに手元にある世界から、サーバーが送ってきたのと同じパケットを組み立てて**、録画の先頭に置きます。

| 保存される物 | 中身 |
| --- | --- |
| 世界そのもの | 入った直後に届いた `GameJoin`（別の次元へ移っていたら `Respawn` も） |
| 地形 | 自分のまわり（**既定6チャンク**）のブロック・バイオーム・ブロックエンティティ、**明るさ** |
| エンティティ | その範囲にいる Mob・アイテム・落下ブロックなどの位置・向き・データ・装備・効果 |
| 自分 | 位置・向き・体力・空腹・経験値・**持ち物**・飛行などの能力 |
| 世界の情報 | 天気（雨・雷の強さ） |

- 組み立てには **バニラがサーバー側で使っているのと同じパケットのコンストラクタ** を使っています
  （`ChunkDataS2CPacket(WorldChunk, LightingProvider, …)` など）。形が変わっても追従できます
- 録り始めに **1回だけ** 作ります（数百チャンクで数十〜百ミリ秒。保存した内容はログに出ます）
- 半径は設定で変更できます。**0 にすると保存しません**（録り始めが軽くなる代わりに、途中からの録画は再生できなくなります）

制限:

- **他のプレイヤーは、サーバーが録画中に情報を送ってきた時点から** 現れます
  （タブリストの情報を持っていないので、写しには入りません）
- **この Mod を入れる前から入っていたワールド** では写しを作れないので、いちど入り直してください
  （その場合、従来どおり理由を書いた画面が出ます）

## パケットにならない操作も記録する

パケットは「サーバーとやりとりした内容」しか残りません。
**ローカルでだけ起きる操作** はパケットにならないので、別に記録しています
（プレビューでも書き出しでも、そのとおりに再現されます）。

| 記録する物 | 中身 |
| --- | --- |
| マウスカーソル | インベントリのどこを指していたか |
| 入力中の文字 | チャット欄に **打っている途中** の文字（送るまでサーバーには届きません） |
| 視点（F5） | 一人称 / 三人称 / 三人称(前) |
| デバッグ画面（F3） | F3 の表示・非表示 |
| 開いている画面 | インベントリ・チェスト・チャットなど（**画面の種類だけ**。中身はパケットに残ります） |

- ぜんぶ **差分** です。動いていないときは1バイトも書きません
  （カーソルは移動量、入力中の文字は増えた分だけ。ときどき全体を混ぜて崩れにくくしています）
- 再生中は **バニラの設定そのもの** を動かすので、録っていた本人と同じ見え方になります
- プレビューの画面の上に「開いていた画面」と「入力中の文字」が出ます
- とても小さいので、容量を気にせず記録できます

## 音声も一緒に録る

音は「いま鳴っている物」をその場で取るしかないので、**録画と同時に** 録ります
（書き出しのときには、もうその音は存在しません）。

| 設定 | 録れる音 | しくみ |
| --- | --- | --- |
| **Minecraft だけ**（既定） | Minecraft が鳴らした音だけ | OpenAL のループバック（音の出口をいったん自分で受け取る） |
| **PC 全体** | PC が鳴らしている音ぜんぶ（VC の声も含む） | ffmpeg で OS の入力から取る |
| 録らない | — | いままでどおり |

- **VC Mod（Simple Voice Chat）の声は別に録ります。** Minecraft の音とは別ファイル
  （`.voice.ogg`）になるので、書き出しのときに **「VC の音声を含める」を ON / OFF できます**
- 音声は **Opus**。録画の隣に別ファイル（`.audio.ogg` / `.voice.ogg` / `.system.ogg`）として置かれるので、
  本体の録画には一切手を入れません（音声だけ消しても壊れないし、無くても再生できます）
- 録れない環境（ffmpeg が無い、機器が無い、OpenAL が非対応など）でも **録画そのものは必ず残ります**。
  「Minecraft だけ」が使えないときは **PC 全体の音へ回します**（無音よりマシなので）
- プレビューでは音は鳴りません（書き出しの動画に入ります）

「Minecraft だけ」を選んだときの挙動:

- 録り始めと録り終わりに **音の再読み込み** が入ります（装置を差し替えるため。1回だけです）
- 取り出した音はそのまま実機へ流すので、**録っていても音はふだんどおり聞こえます**

「PC 全体」を選んだときに必要な物:

| OS | 必要な物 |
| --- | --- |
| Windows | ステレオミキサー（有効にする）か、VB-CABLE などの仮想デバイス |
| Linux | PulseAudio / PipeWire（たいてい最初から入っています） |
| macOS | BlackHole などの仮想デバイス（**標準では取れません**） |

機器は設定画面の **「機器を探す」** で一覧から選べます（空欄なら自動で選びます）。

## クリップ方式（Medal みたいに「あとから保存」）

設定の **「クリップ方式」** を ON にすると、入った瞬間から録り続けますが、
**保存しなければ何も残りません**。「いまのプレイ、すごかった」と思ったら
ポーズメニューの **✂ クリップ保存** を押すだけ。押した時点から
**設定した秒数ぶんだけ遡って** 1つの .ifreplay になります（Medal と同じ感覚です）。

しくみ（軽さと引き換えにしている所）:

- 録り始めから **短い区間（5分が目安。短い設定では4分の1）ごとにファイルを分けて** 書き、古い区間から捨てます
  - メモリには溜めません（書き込みスレッドがこまめにファイルへ移すので、長時間遊んでも平気）
- 捨てるのは **「設定した長さの1.5倍」より古い区間** と **容量の上限を超えた分**（先に来たほう）
  - 容量はふつう「いまの書き込み速度」から自動で決めます（ディスクが一杯にならず、SSD に書く量も増えません）
- 区間の先頭には **その時点の世界の写し** が入っています
  - どの区間からでも「そこに世界がある状態」から再生できるので、**つなげた結果が必ず再生できます**
- 保存するときは **残っている区間をそのままつなげるだけ**（再圧縮もしません）
  - 数十秒ぶんのコピーなので一瞬です。別スレッドでやるのでゲームは止まりません
- 音声は区間と違って **ずっと録り続け**、保存時にいちばん後ろのぶんだけを ffmpeg で切り出します
  - 音は「止めて録り直す」と途切れるためです。保存した瞬間に **書き出し先を次のファイルへ移すだけ**
    （装置は開いたまま）なので、つづけて何回保存しても**毎回きちんと音が付きます**
  - VC の声も別ファイルのまま切り出されます

長さの目安: 開始位置は必ず区間の先頭（＝世界の写しがある所）になるので、
実際のクリップは **設定した長さ〜それに1区間ぶん足した長さ** になります（2時間なら 2〜2時間5分）。
一時ファイルは `<保存先>/.clip-cache/` に置かれ、録画をやめると消えます。

保存したクリップは **`clip_` から始まる名前** で残ります。**「クリップを残す時間」**（既定24時間）
より古い物は、クリップ方式を始めたときと保存したあとに自動で片付きます
（音声ファイルも一緒に消えます。0 にすると消しません）。

## 編集（範囲を切り出す）

録画一覧の **「編集」** ボタン（または再生中の **✂ 編集**）から、
保存済みクリップの前後トリム・中抜きができます。見ながら
**I 始点 / O 終点** で区間を決め、**+ 残す / − カット** で範囲を作り、
**✂ 高速出力** で別ファイルに切り出します（すぐ動画にするなら **🎬 mp4で出力** で書き出し画面へ直行）。

- 再レンダはしません（パケットを複写するだけ）。速いし劣化もしません。音声も範囲に合わせて付きます
- 先頭を落とすと、直前の「写しがある場所」から前書きとして付けます
  （そこから再生できる状態にするため）。再生・書き出しは自動で「ここから見せる」位置から始まるので、前書きは見えません
- 真ん中を抜いたつなぎ目は、多少乱れることがあります（画面にも注意が出ます）
- 切った物をまた切れます（`_edit`、`_edit_2`…と別名で残ります。元は変わりません）

## 書き出し（動画にする）

録画一覧の **「書き出し」** ボタンから、録画を動画ファイル（`.mp4`）にできます。

- **FPS・解像度・ビットレートは録画とは無関係に選べます。** 60fps で録って 30fps で出す、
  ウィンドウより大きな 4K で出す、といったことがあとから何度でもやり直せます
- 書き出す**範囲**（開始〜終了）も指定できます
- **GPUエンコード（既定オン）** でmp4を作ります。NVIDIA / Intel / AMD / Apple を自動で探し、
  無ければ CPU（x264）に切り替わります。目次は先頭に置くのでブラウザ等ですぐ再生できます
- **バニラの HUD（ホットバー等）は隠しません。** プレイヤー自身が **F1** で隠しているときだけ、
  そのまま隠れた状態で書き出されます（Mod 側で勝手に消すことはしません）
- **「等倍速で描く」（既定オン）** をオンにすると、本番と同じ速さで1枚ずつ描きます。
  モーションブラーの蓄積やテンポラル系のシェーダーなど「実時間」を見る Mod の演出が
  本番どおりになります。オフにすると GPU の速さしだいで一気に進むので速いぶん、
  それらの演出の効き方が変わります

| 項目 | 内容 | 既定値 |
| --- | --- | --- |
| FPS | 動画の1秒あたりの枚数（24 / 30 / 50 / 60 / 120 / 144 / 240 から選択） | 60 |
| 解像度 | 1280×720 / 1920×1080 / 2560×1440 / 3840×2160 / **画面と同じ** / 手入力 | 1920×1080 |
| ビットレート | 大きいほど綺麗でファイルも大きい（1080p60 なら 10000〜20000 が目安） | 20000 kbps |
| ffmpeg の場所 | パスが通っていれば `ffmpeg` のままで大丈夫 | `ffmpeg` |
| ファイル名 | 保存先は `ifuto-replay/exports/`（同じ名前なら `_2` を付ける） | 録画と同じ名前 |
| 開始 / 終了 | 書き出す範囲（スライダー） | 全体 |
| 音声を含める | いっしょに録っておいた音声を動画に入れる（音声がある録画だけ出ます） | オン |
| VC の音声を含める | Simple Voice Chat の声を入れるかどうか | オン |

しくみ（画面録画との違い）:

- **時間をこちらで進めます。** 1枚描くごとに「録画の時刻」を 1/FPS 秒だけ進めて描かせ、
  できた絵を `ffmpeg` に rawvideo（`rgba`）のパイプで渡します
- 実時間とは無関係なので、**重いシーンでもカクつきません**（そのぶん時間はかかります）
- 絵の取り込みは**バニラのスクリーンショットの経路**をそのまま借りています
  （GL の読み出しを自前で書かないので、バージョンが変わっても壊れにくい）
- 書き出し中は解像度に合わせてフレームバッファを広げて HUD を隠し、**終わったら元に戻します**
- 進捗画面で**中断**できます。ffmpeg が無い・解像度が合わない等は、理由を出して一覧に戻ります

> [!NOTE]
> **ffmpeg は同梱していません。** 別途インストールして、パスを通すか
> 設定の「ffmpeg の場所」に実行ファイルのフルパスを書いてください。

> [!TIP]
> 書き出し中は **ウィンドウの大きさを変えないでください**（解像度が変わってしまうので、
> 気づいた時点で中断します）。時間はかかるので、録画は短く切っておくと楽です。

## ロードマップ

1. ✅ **録画コア** — パケットの取りこぼしなし保存・非同期書き込み・しおり・インジケータ
2. ✅ **再生プレビュー** — 録ったパケットをバニラの世界に流し込み、
   一時停止・倍速・しおり移動・シーク（バーをドラッグ）・リソースパック / Iris の切り替え
3. ✅ **書き出し**（この版）— 任意の **FPS / 解像度 / ビットレート** で1枚ずつ描かせ、
   ffmpeg へ rawvideo のパイプで渡して動画にする（範囲指定・中断つき）
4. ✅ **途中から録り始めた録画の再生** — 録り始めの時点の「地形と实体の状態」を
   バニラと同じパケットとして組み立てて一緒に保存し、いつ録り始めても再生できるようにした
5. ✅ **メモリと容量の自動管理**（この版）— 溜めたデータは定期的にファイルへ移し、
   メモリの上限は環境から自動で決める。空き容量が少なくなったら知らせ、足りなくなる前に保存して止める
6. ✅ **パケットにならない操作の記録** — カーソルの位置・入力中の文字・F5・F3・
   開いている画面を差分で記録し、再生時にバニラの設定へ反映する
7. ✅ **音声** — **Minecraft だけ** / **PC 全体** を選んで録り、書き出しで一緒にする。
   **VC Mod（Simple Voice Chat）の声は別に録る** ので、書き出しのときに入れるか選べる
8. ✅ **GUI を今っぽく** — 角丸の面・トグル・細いスライダー・進捗バー。
   描き方だけ差し替えているので、操作感と読み上げはバニラのまま
9. ✅ **クリップ方式** — Medal のように録り続け、押した時点から
   **遡って数秒ぶんを1本の録画にする**。区間ごとに分けて古い物から捨てるので
   メモリは増えない。区間の先頭に世界の写しを入れてあるので、つなげた結果は必ず再生できる
10. ✅ **数時間ぶんのクリップ**（この版）— クリップの長さを **最大4時間** まで選べるようにし、
    一時ファイルの上限を **書き込み速度から自動で** 決めるようにした（空きの4分の1まで。
    SSD に書く量も増えない）。保存しても **音声を止めない** ので、つづけて何回保存しても
    毎回音が付く。置き場が足りないときは、壊れたファイルを残さずに知らせる

## サーバーで BAN されませんか？

**この Mod が原因で「通信内容」から BAN されることはありません。** 理由は次のとおりです。

| 観点 | この Mod |
| --- | --- |
| パケットの送信 | **一切しない**。受信・送信ともに「読むだけ」で、書き換えも追加もキャンセルもしません |
| サーバーから見える通信 | バニラと **1バイトも変わらない**（覗いたあと必ずそのまま流します） |
| Mod の名乗り | しない。サーバーがチャンネルを聞いてきても答えません |
| 自動操作（オートクリック等） | ありません |

つまり Grim / Vulcan / NCP / AAC のような**挙動・パケット解析型のアンチチートでは検知できません**
（ReplayMod や Flashback と同じ部類です）。

それでも気をつけたい点だけ:

1. **サーバーの規約**。録画・配信そのものを禁止しているサーバーはあります。
   録る前にそのサーバーのルールを確認してください
2. **「操作も記録」をオンにすると、自分の送信パケットも保存します**。
   保存はローカルだけでサーバーには何も送りませんが、直列化ぶんだけ送信がわずかに遅れます
   （気にするなら設定でオフに。S2C だけの記録になります。オフでも自分の移動だけは残すので、再生時のカメラは動きます）
3. **録画データの取り扱い**。ファイルにはアカウント名・接続先・チャット本文が入ります。
   他人に渡すときは注意してください
4. **「再生」も送信ゼロのローカル再生** です。何も送らない接続を渡して、録ったパケットを
   バニラの世界に流し込んでいるだけなので、再生中もサーバーとの通信は発生しません
